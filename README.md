# Resolve Project Search

[![build](https://github.com/1977-code/bro-resolve-search/actions/workflows/build.yml/badge.svg)](https://github.com/1977-code/bro-resolve-search/actions/workflows/build.yml)

Находит, в каком проекте DaVinci Resolve лежит нужный клип.

Указываешь папку с `.drp`, вводишь имя файла — получаешь список проектов, в которых
он встречается. Без Resolve, без базы данных, без открытия проектов по одному.

## Что умеет версия 1.0

- поиск по имени файла или его части во всех `.drp` в папке и подпапках;
- многопоточное сканирование, прогресс-бар и мгновенная отмена;
- раскрытие проекта показывает сами найденные строки — видно, что именно совпало;
- двойной клик открывает папку с проектом, правый клик — копирование пути;
- экспорт результатов в CSV, который открывается в Excel без плясок с кодировкой;
- ничего не пишет и не изменяет: файлы открываются только на чтение.

Поиск идёт по строкам внутри файла проекта, поэтому находит клип независимо от
того, лежит ли имя в имени клипа, в пути к медиа или в свойствах. Обратная
сторона: версия 1.0 говорит **в каком проекте**, но ещё не говорит, на каком
таймлайне и в каком таймкоде — это версия 2.0, см. ниже.

## Скачать

Готовые `.exe` для Windows собираются в GitHub Actions на каждый тег и лежат в
[Releases](../../releases). Python на целевой машине не нужен.

- **ResolveProjectSearch.exe** — сам поиск.
- **ResolveDoctor.exe** — диагностика: собирает сведения о DaVinci Resolve,
  базах проектов и формате `.drp` на реальной машине. Инструкция для того, кто
  будет её запускать: [docs/DIAGNOSTICS.md](docs/DIAGNOSTICS.md).

## Установка для разработки

```bash
python3 -m venv .venv
./.venv/bin/pip install -e ".[dev]"
./.venv/bin/resolve-project-search
```

Тесты:

```bash
./.venv/bin/pytest
```

## Командная строка

Тот же движок без окна — удобно для скриптов и рендер-нод:

```bash
resolve-project-search "J:\Проекты" C6343.MP4 --verbose --csv result.csv
```

Код возврата `0` — что-то найдено, `1` — не найдено, `2` — папки нет.

## Сборка .exe для Windows

Собирать нужно **на Windows** — PyInstaller не делает кросс-сборку.

## Формат .drp

Формат проектов Resolve не документирован публично и менялся между версиями,
поэтому приложение ничего о нём не предполагает: оно определяет контейнер по
сигнатуре в первых байтах (ZIP, gzip, zlib, SQLite, текст, двоичный) и работает
с тем, что нашло. Если контейнер распаковать не удалось, файл всё равно
сканируется как есть — «не смогли прочитать» никогда не превращается в
«совпадений нет».

Чтобы строить версию 2.0 на фактах, а не на догадках, в комплекте есть две
диагностики:

```bash
resolve-doctor                       # окно: Resolve, базы проектов, файлы .drp
rps-probe "J:\Проекты" --out drp.md  # только разбор формата .drp
```

`resolve-doctor` отвечает на главный вопрос — **где вообще лежат проекты**.
Файл `.drp` существует только если проект вручную экспортировали; обычно
проекты живут в базе Resolve, и тогда поиску по папке искать нечего. Диагностика
проверяет оба варианта: считает проекты в базе через API и ищет `.drp` на дисках.

Подробности и текущий статус знаний о формате — [docs/FORMAT.md](docs/FORMAT.md).

## Дальше

- **2.0** — структурный разбор: проект → таймлайн → дорожка → таймкод → клип →
  путь. Аналог Find Usage, но сразу по всем проектам. Требует отчёта `rps-probe`
  с реальных файлов.
- **3.0** — поиск по Reel Name, Tape Name, Camera Roll, маркерам, названиям
  таймлайнов и тексту Text+; индекс с инвалидацией по mtime, чтобы сотни
  проектов искались за доли секунды.
- Импорт найденного проекта прямо в Resolve — пункт меню уже есть, но выключен,
  пока доступ к скриптовому API не проверен на живой установке.
