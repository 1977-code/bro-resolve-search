# Resolve Doctor — что запустить на компьютере с DaVinci

Это инструкция для того, у кого стоит DaVinci Resolve и лежат проекты. Ничего
устанавливать не нужно, Python не нужен, одна программа — один клик.

## Что делать

1. Открыть страницу [Releases](../../releases) и скачать **ResolveDoctor.exe**.
2. **Запустить DaVinci Resolve** и открыть в нём любой свой проект — обычный,
   рабочий, не пустой. Так программа сможет проверить живой доступ к Resolve,
   а не только файлы на диске.
3. Запустить `ResolveDoctor.exe`. Windows может показать синее окно
   SmartScreen — это потому, что файл не подписан сертификатом, а не потому, что
   с ним что-то не так: «Подробнее» → «Выполнить в любом случае».
4. Нажать **«Собрать отчёт»** и подождать. Обычно меньше минуты; поиск файлов
   `.drp` по всем дискам может занять до двух.
5. Когда откроется папка — прислать оттуда **два файла**: `resolve_doctor_….md`
   и `resolve_doctor_….json`. Они лягут на рабочий стол.

Всё. Дальше по ним дописывается сам инструмент.

## Что программа делает

Только читает. Она:

- смотрит, какая версия Resolve установлена и запущен ли он;
- проверяет, доступен ли скриптовый API (и если нет — называет причину);
- спрашивает у Resolve, какие есть базы проектов и сколько в них проектов;
- ищет на дисках файлы `.drp` и разбирает несколько из них, чтобы понять формат.

Чего она **не** делает: не открывает и не загружает проекты, ничего не создаёт,
не переименовывает и не удаляет, никуда не отправляет данные — файлы просто
сохраняются на рабочий стол.

## Что попадает в отчёт

Пути и имена файлов с этого компьютера: имена проектов, папки, названия
исходников. Без них нельзя разобрать формат — по этому отчёту пишется парсер.

Оба файла — обычный текст, их можно открыть блокнотом и посмотреть перед
отправкой. Если что-то из этого не должно уезжать, просто удали эти строки:
отчёт от этого станет менее полным, но останется полезным.

## Если что-то пошло не так

- **Окно не открылось вообще** — скорее всего антивирус удалил файл. Однофайловые
  сборки часто ловят ложные срабатывания, потому что распаковывают себя во
  временную папку.
- **Написано, что скриптовый API не подключился** — это нормальный результат, а
  не поломка. Чаще всего помогает: запустить Resolve, открыть проект, и в
  Preferences → System → General включить *External scripting using* → Local.
  После этого запустить диагностику ещё раз.
- **Диагностика прервалась с ошибкой** — пришли текст прямо из окна программы.
  Это ошибка самого инструмента, и чинится она по этому тексту.

## Из командной строки

Если удобнее без окна:

```
ResolveDoctor.exe --out C:\Temp\report --seconds 180
```

`--no-drp-search` пропустит поиск по дискам, `--home-only` ограничит его папкой
пользователя.
